Methodology · How I keep the multi-agent builds honest

Anti-drift governance for multi-agent codebases

Point several AI agents at the same codebase and they ship fast - and they also drift: a button wired to a dead file, a lint step nobody hooked into CI, a database migration written but never run, an LLM's judgment computed and then silently discarded before it reached the database. I found and fixed exactly that class of bug auditing my own JobForge platform, then turned the fix into a repeatable practice I now apply at the start of every multi-agent project.

  • Architecture mapping: a current map of every module, route, and data flow - verified by reading the real code and grepping real call sites, not by trusting old docs.
  • Wiring audits: every exported function checked for a real caller, every DB column checked for a real reader, every frontend call checked against a real backend route and back.
  • Change protocols: a task isn't done until the code, the docs, and the tests agree - and new agent work has to trace back to the active goal, not just look busy.
  • Documentation harnesses: goal docs, docs indexes, and orchestration protocols that give agents - and me - a durable record of what's actually been built, independent of any one session's memory.
